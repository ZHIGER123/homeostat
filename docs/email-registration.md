# Подтверждение email при регистрации

Нажатие «Зарегистрироваться» отправляет шестизначный код. После успешного ответа появляется поле кода и кнопка «Подтвердить email». До проверки нового кода запись пользователя и токен входа не создаются. Оба маршрута `/api/v1/register` и `/api/v1/auth/register` также требуют подтверждения: возвращают 202, а не аккаунт с токеном.

По умолчанию код действует 10 минут, повторная отправка доступна через 60 секунд, лимит неверных попыток — 5. Настройки: `EMAIL_OTP_TTL`, `EMAIL_OTP_RESEND_SECONDS`, `EMAIL_OTP_MAX_ATTEMPTS`. Код и пароль хранятся в виде хешей. Повторное использование кода запрещено. Операции для одного email сериализованы cache-lock; используйте общее хранилище cache для всех экземпляров приложения.

## Реальная доставка через SMTP

API-ключ не обязателен: достаточно SMTP-учётных данных провайдера. Если провайдер использует API-ключ как SMTP-пароль, внесите его в `MAIL_PASSWORD`. Не публикуйте секреты в GitHub, чатах, скриншотах или `.env.example`.

Добавьте в локальный/серверный `.env` реальные значения, выданные вашим почтовым сервисом:

```dotenv
MAIL_MAILER=smtp
MAIL_SCHEME=smtp
MAIL_HOST=smtp.your-provider.example
MAIL_PORT=587
MAIL_USERNAME=your-smtp-username
MAIL_PASSWORD=your-smtp-password
MAIL_FROM_ADDRESS=no-reply@your-verified-domain.example
MAIL_FROM_NAME=Homeostat
```

Это шаблон, не рабочие реквизиты. Для порта 587 обычно используется `smtp` с автоматическим STARTTLS; для порта 465 — `smtps`. Следуйте параметрам вашего провайдера. `MAIL_ENCRYPTION` не используется текущим `config/mail.php`: настройка схемы называется `MAIL_SCHEME`. Если задан `MAIL_URL`, он может переопределять отдельные SMTP-параметры: удалите старое значение или настройте его согласованно.

Подтвердите домен/адрес отправителя у провайдера, настройте SPF/DKIM и при необходимости DMARC. Доставка внешним адресатам может быть ограничена sandbox-режимом провайдера.

```sh
php artisan optimize:clear
php artisan migrate
npm install
npm run build
php artisan test
```

Новых миграций для этой доработки нет: используются существующие таблицы пользователей, кодов подтверждения и cache. Письмо отправляется синхронно, queue worker для этой функции не требуется. SMTP-таймаут — 15 секунд.

`MAIL_MAILER=log` не доставляет письма. Вне тестов регистрация теперь возвращает понятную ошибку 503 при log/array или неподдерживаемом транспорте, а не сообщает об успешной отправке. Для доставки выберите прямой SMTP или поддерживаемый почтовый транспорт; составные log-fallback транспорты намеренно не разрешены. При SMTP-ошибке новый код аннулируется, пользователь не создаётся.

Существующий email можно подтвердить тем же кодовым входом через `/auth/email/request-code`; сохранённый пароль при этом не меняется. Новые аккаунты всегда получают роль listener независимо от переданной роли artist.

## Проверка после настройки

Зарегистрируйте новый адрес, проверьте входящие/спам, введите код, убедитесь, что аккаунт создаётся только после подтверждения. Повторный ввод того же кода должен вернуть ошибку. Успешная передача письма SMTP-серверу не гарантирует попадание во «Входящие» — проверяйте логи и репутацию отправителя у провайдера.

Добавлены backend-тесты отправки Mailable, подтверждения, одноразовости, срока действия, лимита попыток и отказа SMTP. Их необходимо выполнить в PHP-окружении проекта; браузерные проверки с имитацией API не проверяют реальную доставку.
