# Регистрация с подтверждением email во всплывающем окне

## Поведение

1. Пользователь заполняет прежнюю форму: имя, email, дату рождения, пароль, повтор пароля и CAPTCHA.
2. Нажимает «Зарегистрироваться». Проверяются поля, возраст 16+ и CAPTCHA; сервер отправляет код.
3. Только после успешного приёма письма почтовым сервисом открывается отдельное модальное окно «Подтвердите email» с адресом получателя и полем для шести цифр.
4. Правильный код создаёт аккаунт с подтверждённым email и выдаёт токен входа. Неверный/просроченный код аккаунт не создаёт.

Закрытие окна крестиком или Escape не теряет введённую форму. Кнопка «Ввести код подтверждения» открывает окно снова. «Изменить email или данные» возвращает к форме. Повторная отправка разрешена через 60 секунд. Для неё используется зашифрованный ограниченный по времени токен, привязанный к email: вводить CAPTCHA повторно внутри окна не требуется. Для другого email токен не подходит.

Код одноразовый, хранится в виде хеша, по умолчанию живёт 10 минут и допускает 5 неверных попыток. Параметры: `EMAIL_OTP_TTL`, `EMAIL_OTP_RESEND_SECONDS`, `EMAIL_OTP_MAX_ATTEMPTS`. Пароль в ожидающей регистрации также хранится только как хеш. Блокировка cache сериализует операции одного email; для нескольких серверов используйте общее хранилище cache.

## Реальная доставка через Resend

Добавлен серверный `RegistrationMailService`: отправляет письмо через HTTPS API Resend. Ключ остаётся на сервере; браузер его не получает. SDK, новые Composer-зависимости и queue worker для отправки кодов не требуются.

Для активации необходимы ваш аккаунт Resend, подтверждённый домен отправителя и API-ключ с правом отправки для этого домена. Создание сервиса и запись кода в репозиторий не заменяют авторизацию: без настоящего ключа и подтверждённого адреса реальной доставки нет.

1. Создайте аккаунт https://resend.com и добавьте свой домен в Domains.
2. Добавьте DNS-записи, указанные Resend (в том числе SPF/DKIM), дождитесь подтверждения домена.
3. Создайте API-ключ с минимально необходимыми правами отправки.
4. На своём компьютере/сервере, в приватном `.env`, задайте:

```dotenv
MAIL_MAILER=resend
RESEND_API_KEY=YOUR_REAL_RESEND_KEY
MAIL_FROM_ADDRESS=no-reply@YOUR_VERIFIED_DOMAIN
MAIL_FROM_NAME=Homeostat
```

Это шаблон, не готовые рабочие реквизиты. Для отправки любым пользователям используйте собственный подтверждённый домен, а не тестового отправителя. Ключ нельзя присылать в чат, коммитить в GitHub, включать в скриншоты или переменные `VITE_*`.

После изменения `.env`:

```sh
php artisan optimize:clear
npm install
npm run build
php artisan test
```

Проверьте регистрацию на реальном адресе и события отправки/доставки в Resend. Успешный приём API не гарантирует попадание во «Входящие»: учитывайте лимиты, sandbox-ограничения, спам-фильтры и репутацию домена. Сервер должен иметь HTTPS-доступ к `api.resend.com`.

При отсутствии ключа или отказе сервиса API возвращает понятную ошибку 503, а не ложное сообщение об отправке. При сбое доставки новый код аннулируется. В модальном окне сохраняются данные при неверном коде; письмо не отправляется повторно от нажатия кнопки подтверждения.

## SMTP как альтернатива

Если SMTP уже настроен, можно сохранить его: `RegistrationMailService` передаст письмо стандартному Laravel Mail.

```dotenv
MAIL_MAILER=smtp
MAIL_SCHEME=smtp
MAIL_HOST=smtp.YOUR_PROVIDER
MAIL_PORT=587
MAIL_USERNAME=YOUR_USERNAME
MAIL_PASSWORD=YOUR_SMTP_PASSWORD
MAIL_FROM_ADDRESS=no-reply@YOUR_VERIFIED_DOMAIN
MAIL_FROM_NAME=Homeostat
```

Для порта 465 обычно используется `MAIL_SCHEME=smtps`; следуйте настройкам провайдера. Устаревший `MAIL_ENCRYPTION` в текущей конфигурации не используется. Если задан `MAIL_URL`, проверьте, что он не переопределяет эти настройки. `MAIL_MAILER=log` письма не доставляет и вне тестов не допускается для регистрации.

Новых миграций нет. Используются существующие таблицы пользователей, кодов и cache. Существующие endpoints `/register` и `/auth/register` не позволяют создать новый аккаунт в обход email-кода. Существующий email не допускается ни к повторной регистрации, ни к отправке регистрационного кода, ни к подтверждению старым кодом. Email сравнивается без учёта регистра и внешних пробелов. Сервер возвращает 422 с ошибкой поля email: «Этот email уже зарегистрирован. Войдите в существующий аккаунт». Регистрационный код больше не используется как беспарольный вход в существующий аккаунт; для него остаётся обычный /login. Проверка повторяется в сервисе и при потреблении кода, а UNIQUE-индекс users.email защищает создание от дубликатов. Действительный resend_token не обходит запрет.

## Проверки

Backend-тесты включают вызов Resend через Http fake, правильного адресата и код, отсутствие аккаунта до проверки, отказ провайдера, отсутствие ключа и повторную отправку с привязанным токеном. Они не доказывают реальную доставку. В окружении разработки без PHP тесты необходимо отдельно выполнить на машине проекта.


Регрессионные проверки запрета повторной регистрации:

```sh
php artisan test --filter=EmailRegistrationTest
php artisan test --filter=AuthApiTest
```

Охвачены три маршрута начала регистрации, регистр/пробелы email, старый код для существующего или заблокированного аккаунта, legacy email с заглавными буквами и повторная отправка после создания аккаунта. Эти проверки не являются обещанием блокировки одного человека с разными email: для такого ограничения нужна отдельная подтверждённая идентификация.
