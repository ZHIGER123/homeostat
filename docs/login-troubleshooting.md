# Вход, выход и ограничения

Оба маршрута POST /api/v1/login и POST /api/v1/auth/login используют один именованный limiter login. Лимит 5 запросов/минуту применяется к сочетанию нормализованного email и IP. Дополнительный предел 60 запросов/минуту на IP защищает от обхода перебора сменой адресов. Роли listener, artist и admin обрабатываются одинаково; привилегированного обхода защиты нет. Порог учитывает все запросы входа, включая успешные.

429 возвращает Retry-After, retry_after и русское сообщение. Клиент не отправляет повторные запросы автоматически, блокирует двойной submit и показывает обратный отсчёт. Неверный пароль остаётся ответом 401 с сообщением «Неверный email или пароль», а не «Сессия истекла».

Выход выполняется POST /api/v1/logout с текущим токеном. GET был ошибкой клиента и приводил к 405; при сетевой ошибке клиент теперь не заявляет успешный отзыв токена.

После обновления: php artisan optimize:clear, npm run build (или перезапустить npm run dev), затем жёстко обновить страницу. Миграций нет. При оставшихся 429 дождитесь Retry-After и проверьте один запрос на одно нажатие в Network. Не отключайте limiter и не удаляйте пользовательскую БД.

Проверки: php artisan test --filter=LoginThrottleTest; php artisan test --filter=EmailRegistrationTest; php artisan test. Браузерный стенд с тестовыми API-ответами отдельно проверяет двойной submit, 401, 429/таймер и POST-выход; он не подменяет PHP-тесты.
