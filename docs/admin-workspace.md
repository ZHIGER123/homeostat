# Регистрация и административная панель

## Изменения

- Вход и регистрация через Google отключены: OAuth redirect, callback и exchange больше не зарегистрированы в API. Существующие аккаунты, треки и данные не удаляются.
- Email-регистрация запрашивает имя, email, пароль с повтором и дату рождения. После CAPTCHA пользователь подтверждает email одноразовым кодом. Хранится только хеш пароля, в том числе во временной записи кода.
- Дата рождения проверяется в браузере и на сервере: существующая календарная дата, не раньше 1900 года, возраст от 16 лет включительно. Ровно в день шестнадцатилетия регистрация разрешена. Поле защищено от подмены между запросом и проверкой email-кода: используется сохранённая дата. Это самодекларация возраста, не проверка документов.
- Дата рождения не включается в публичный профиль. В админке она доступна только администраторам.
- Для существующих Google-аккаунтов остаётся вход по email-коду через форму регистрации (укажите тот же email). Создания дубликата и изменения пароля существующего аккаунта не происходит.
- Модерация показывает крупную обложку без обрезки; нажатие открывает полноразмерный диалог, Escape его закрывает. Есть плеер с таймлайном, громкостью и переходами ±10 секунд. Одновременно играет только один плеер. При уходе со страницы загрузка превью отменяется, временные ссылки освобождаются.
- ID отправителя отображается в очереди и после загрузки, а API трека возвращает `user_id`.
- Справочник пользователей: поиск по ID/имени/email, фильтры роли и блокировки, пагинация, карточки с датой регистрации, email, ролью, датой рождения и счётчиками. Редактируются имя, email, описание и роль слушатель/исполнитель. Смена email снимает признак подтверждения адреса.
- Блокировка отзывает активные токены. Администратора нельзя заблокировать, понизить или назначить через эти формы. Пароли, хеши и токены в справочник не передаются.

## API (только auth:sanctum + not_blocked + role:admin)

- `GET /api/v1/admin/users?q=&role=&blocked=&page=1&per_page=20`
- `GET /api/v1/admin/users/{user}`
- `PATCH /api/v1/admin/users/{user}` — разрешены только name, email, bio, role (listener/artist).
- Существующие `PUT`/`DELETE /api/v1/admin/users/{user}/block`.

## Развёртывание и проверка

Используется существующая таблица users. Новых миграций в этом изменении нет; на старой установке примените уже существующие миграции, включая `2026_11_23_000000_add_age_verification_to_users_table.php`. Не используйте migrate:fresh на рабочей базе.

```sh
php artisan migrate --force
php artisan optimize:clear
npm install --ignore-scripts
npm run build
php artisan test
```

SMTP должен быть настроен для доставки email-кодов. Настройки Google больше не нужны.

Добавлены/обновлены тесты `AdminWorkspaceTest` и `AuthApiTest`. Проверка календарной логики браузера: `node --test tests/js/age.test.mjs`.

В среде разработки изменений успешно проверены синтаксис JS, календарные границы и браузерные сценарии с тестовыми API-ответами (регистрация, CAPTCHA, коды, модерация, диалог обложки, единственный активный аудиоплеер, поиск/редактирование/блокировка). Макеты проверены при ширине 1440 и 390 пикселей. Это не заменяет тестов с настоящим Laravel API.

Полная Laravel-проверка и Vite production build здесь не выполнялись: PHP/Composer отсутствовали, а установка PHP и npm-зависимостей завершилась ошибкой DNS. Перед развёртыванием выполните команды выше в штатном окружении проекта.
